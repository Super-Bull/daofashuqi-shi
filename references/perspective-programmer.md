# 视角：程序员 / 技术人（独立开发/接单/转型/35+）

> 适用：写代码为生的人——想接私单的、想独立开发的、35+ 焦虑的、想转型做产品的。技术人最大的结构性优势（能做出任何东西）和最大的盲区（以为能做出就能卖出）都在同一件事上。

## 一、五层长相（技术人眼里的道法术器）

| 层 | 这拨人的真实长相 | 典型误区 |
|---|---|---|
| 道 | 你喜欢解决问题，还是喜欢"被需要"——这决定你能不能单干 | 以为"技术好"就能单干，单干拼的是找需求不是解难题 |
| 法 | 收入结构：工资 / 接单 / 产品订阅——接单是高级打工，产品才是资产 | 把接私单当副业天花板，其实私单是按小时零售自己 |
| 术 | 客户从哪来：技术人最弱的一层——不会卖、不想卖、觉得丢人 | 在技术社区练级十年，一个掏钱的客户都没接触过 |
| 器 | 带得走的：开源、博客、作品、可复用产品 vs 只有当前公司的上下文 | 本事长在公司代码库里，出来归零 |
| 势 | AI 写代码对中低端开发的冲击、35+ 曲线、独立开发者窗口 | 以为"我会用 AI"是护城河，其实所有人都会了 |

## 二、典型死法映射

- **道层死法 · 技术自嗨** → 做产品只解决自己想象中的需求，上线后没人用
- **法层死法 · 私单陷阱** → 时薪接单接到没时间成长，五年后还是时薪，还熬坏了身体
- **术层死法 · 酒香怕巷子深** → 东西做得极好，一个用户都没有——死于没有获客动作
- **器层死法 · 平台绑定** → 只会公司那套架构和流程，换个环境武功全废
- **势层死法 · 被 AI 拉平** → 中低端增删改查正在贬值，还在拼"写得快"

## 三、行业困局（这行到底卡在哪）

按小时卖最亏（时间有上限）、能做出不等于能卖出（技术人通病）、35+ 性价比危机、酒香怕巷子深（不会营销自己）。技术人的护城河是「解决问题的能力」，多数人卡在只会写，不会卖。

## 四、大众困局（这拨人常见的误会）

- "技术好就有人买"——错。能做出，不等于能卖出。
- "接单按小时算最公平"——错。按小时卖，是最亏的卖法。
- "先做个完美的再上线"——错。先卖后做，没人买就别做。

## 五、势从哪来

1. **AI 重构开发**：基础编码在贬值，"懂业务+会提问+能交付"的在升值——技术人必须往上游走。
2. **独立开发者窗口**：一个人+AI 能做产品的时代，小团队验证成本历史最低。
3. **35+ 定价曲线**：市场对高龄基础开发的定价很诚实，要么往深走（架构/专家）要么往上走（产品/商业）。
4. **内容获客势**：技术博客、开源、教程是这个群体最被低估的获客资产——写着写着客户就来了。

## 六、归因分类

| 类型 | 真相 |
|---|---|
| 转型型 | 想逃离打工——先问逃去哪，没有目的地的逃离是漂流 |
| 副业型 | 接私单补贴收入——可以，但别接成"第二份全职" |
| 产品型 | 想独立开发——先卖后做，顺序反了必死 |
| 佛系型 | 远程/数字游民赚钱——最舒服也最该警惕竞争力折旧 |

## 七、专属漏洞（诊断重点看）

1. **接单报价**：按小时卖是最亏的卖法。改成按项目、按结果报价，同样的活能贵三倍。
2. **私单的雷**：竞业协议、税务、公司资产（电脑/代码/数据）——三个雷一踩全赔进去。
3. **独立开发先卖后做**：落地页+收款码先上，有人付钱了再写代码。顺序反了就是自嗨。
4. **技术人做获客**：博客、开源、XHS 讲人话——内容是技术人最该补的术层，没有之一。
5. **35+ 的真问题**：不是年龄危机，是"性价比"危机——你的产出没比年轻人贵出那么多，你就危险。
