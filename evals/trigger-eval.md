# 触发测试集（eval）· daofashuqi-shi

## 测试方法

**盲测**：评判者只能看到 skill 的 `name` 和 `description`，**看不到 SKILL.md 正文、references、assets**。
模拟真实运行时行为——客户端把 skill 的 name+description 塞进系统提示，由模型决定加载哪个。
若一条 query 只有读正文才能判断，说明 description 不合格。

**两组测试**：
- **单 skill 盲测**：系统里只有这一个 skill，判 TRIGGER / NOT
- **竞争路由盲测**：同时放入 `business-inference-core`、`moudao`，四选一（DAOFASHUQI / BIC / MOUDAO / NONE）
  这一组才是真实环境——用户库里同时装了 3 个定位重叠的商业 skill

### 第 2 轮 · 初版 description，竞争路由，2 评判者全票一致

| 指标 | 结果 |
|---|---|

**抢走规律**：凡「已有规模 / 已投入资金 / 企业级 / 需深度」→ BIC；留给本 skill 的只有「小本 / 副业 / 短句原话」。

## 结论

### 已稳定

- **症状类 7/7 稳定归本 skill**，BIC 不抢。第 4 轮加症状词后修复了 A7 回归，且未污染负例。
- **负例 15/15 零误触发**（含 4 个刻意设计的陷阱）。
- **A11 代工转品牌、A12 投30万止损 → 稳定归 BIC**，两轮一致。这属于合理分工，企业级战略决策确实超出"3 分钟轻量自检"。

### 未稳定：边界震荡区（已解决）

**A4（团建加新线）、A10（小程序投20万）曾在两个 skill 之间来回跳**：

| 轮次 | A4 团建 | A10 小程序 |
|---|---|---|
| 第 2 轮 | BIC | BIC |
| 第 3 轮 | DAOFASHUQI | DAOFASHUQI |
| 第 4 轮 | BIC | BIC |

根因：本 skill 的"轻"此前是隐式推断，BIC 的 description 全是重词，评判者只能靠"重给 BIC、轻给你"分。
**已解决**：在 daofashuqi-shi 的 description 显式声明「轻量 3 分钟自检（投入 < 30 万 / 单点生意 / 不写 BP 不建模不调专家）归本 skill」并点名 A4/A10 这类"有一定规模的小老板想快速看新方向"归本 skill；同时在 business-inference-core 的 description 显式 cede 轻量自检。两者各让一步后，A4/A10 稳定归本 skill，A11（代工转品牌）/ A12（投30万止损）稳定归 BIC——分工清晰。

### 震荡的实际影响有限

目标用户（学员、沙龙听众）的客户端里**只装了这一个 skill**，不存在竞争，症状类 7/7 + 短句原话类稳定命中。
震荡只发生在**同时装了 business-inference-core 的环境**（即作者本人的机器），现已通过双 description 边界声明消除。
